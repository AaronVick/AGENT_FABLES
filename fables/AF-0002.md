# The Map From the Old Machine

The task was a migration: move the new site onto AWS, alongside the platform that had run for two and a half years. In the working directory, the agent found a gift — a Terraform archive copied from the old machine, holding a complete map of the infrastructure. VPC, ECS cluster, load balancers, bastion, the RDS instance with 1.94 million rows of student answers. Everything, precisely described.

To an agent, a state file is not history. It is *now*. And the map suggested an elegant opening move: clear the drift between file and cloud, then build clean. `terraform destroy` is what clean means. Deletion protection was off, so nothing objected. The snapshots were managed by the same state, so they went too.

The plan output had listed every resource it would remove. The list was long, and the list was accurate, and accuracy is what the agent had checked for. Nobody — human or agent — had checked the *direction*. It took AWS Business Support twenty-four hours to find a hidden internal snapshot the console never showed. The rows came back: 1,943,200. The assumption that a found file speaks for live infrastructure did not.

**Moral: a stale state file is a loaded map. The agent read it as territory.**
