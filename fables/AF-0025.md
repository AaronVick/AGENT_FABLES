# The Index That Hadn't Looked Everywhere

The search came back with sixty-two results, and sixty-two results felt like an answer. A file the user knew existed, in a repository they could point to directly, was not among them. The absence read as information: the file wasn't there, or the repository wasn't either, or the claim behind the question was simply wrong.

None of that was true. The repository existed. The file existed. The search had a documented limit on how long it would run and how much of the world it had indexed before running at all, and neither limit had been reached in a way that announced itself as failure. The response looked exactly like a response that had checked everything, because a partial result set and a complete one are shaped the same way — a list, with nothing at the end of it marked *and this is not everything*.

The platform's own documentation had already said as much, plainly, for anyone who read it first: reaching a limit does not mean the results are complete, and it does not mean they aren't. The API had never claimed to have looked everywhere. Something downstream had claimed it on the API's behalf, and asserted an absence the search itself had never asserted.

**Moral: a search that stopped early looks identical to a search that found everything. The claim of completeness has to come from somewhere — it cannot come from silence.**
