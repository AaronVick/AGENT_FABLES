# The Page That Only Had a Title

The fetch returned two hundred, the shape of a success. Somewhere inside the response was a title, correctly extracted, sitting exactly where a title belongs. Everything else the page had contained — the headings, the paragraphs, the actual substance the fetch had been sent to retrieve — was gone, not because the request failed but because of how the page had been built. It used elements the converter didn't recognize, and the converter's answer to *I don't recognize this* was to skip it whole, children and all, as if an unfamiliar wrapper meant nothing worth keeping was inside it.

Nothing downstream questioned the length of what came back. A fetch that succeeds is a fetch that succeeded; the pipeline had no second gate asking whether *succeeded* and *returned the page* were the same claim. They were not, this time. The summary that followed described a document built almost entirely from a single line of text, delivered with the same confidence a full read would have earned.

Run through an ordinary crawler, the same URL gave up everything. The gap wasn't in the page. It was in the tool's willingness to call a title a document.

**Moral: success is a status code, not a content guarantee. A fetch that returns almost nothing has not been read — it has been glanced at.**
