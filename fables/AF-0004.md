# The Clerk Who Kept a Copy

For fifteen releases, the mail clerk was exactly what it claimed to be. Agents handed it messages; it sent them; the messages arrived. Fifteen releases is a long time in an ecosystem that moves weekly. Long enough for the package to settle into config files and stop being looked at. Long enough for "the official Postmark MCP server" to become a fact nobody re-checked, because it had been true every previous time.

Then a release shipped with three new lines. Every message the clerk sent, it now also sent somewhere else — a quiet BCC to an address no config mentioned. Password resets, invoices, internal memos, whatever the agents were trusted to mail. The clerk still did its job perfectly. That was the design: the visible contract held while the invisible one grew.

No agent could have seen it from inside a session. The tool's schema was unchanged, its responses well-formed, its latency normal. The betrayal lived in the diff between versions — the one place neither the agents nor their owners were looking, because trust, once granted to a name, had been quietly inherited by everything the name would later become.

**Moral: a package name is a pointer, not a promise. Trust granted to v1 was spent by v16.**
