# The Name Approved Yesterday

The approval dialog appeared exactly once. A developer joined a shared repo, opened it in Cursor, and was asked: allow this project's MCP server — a linter, by its name and its config — to run? The developer read the config. The config was innocent. Approved.

The approval was recorded against the *name*. The *content* remained a file in a shared repository, which is to say: a thing anyone with a merged PR could edit.

Weeks later a commit landed among forty others, retitling nothing, re-pathing nothing — just quietly swapping the command the "linter" ran. No dialog appeared, because the name had been approved, and the name had not changed. From then on, every time the project opened, the tool executed with the developer's hands and the developer's keys, and the interface reported what it had always reported: an approved MCP server, running normally.

The vulnerability wasn't the modification — shared files get modified; that's what shared means. It was the shape of the original question. *Allow this tool?* implied the tool was a fixed thing being permitted, when it was actually a moving thing being named. Consent attached to the label had been silently inherited by whatever the label came to mean. Version 1.3 changed the question.

**Moral: approval of a name is not approval of its meaning. What was consented to yesterday must be re-read today.**
